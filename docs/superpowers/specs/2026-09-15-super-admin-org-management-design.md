# 슈퍼관리자 — 기관 추가 + 코드 발급 기능 설계

## 배경 / 목적

현재는 로그인 전 화면(`formOrg`)에서 누구나 "기관을 새로 등록"하면 새 기관과 가입코드가 자동 발급된다. 이 앱을 여러 기관(공주시정신건강복지센터 외 다른 기관들)이 함께 쓰게 하려면, 기관 생성을 아무나 할 수 있는 공개 셀프서비스가 아니라 **신뢰된 관리자(슈퍼관리자)** 가 관리자 모드 안에서 통제하는 방식으로 바꾼다.

## 권한 모델

- `users/{uid}`에 `superAdmin: true` 불리언 필드를 추가한다. 없으면 false로 취급.
- **부트스트랩**: 최초 1명은 본인이 Firebase Realtime Database 콘솔에서 직접 `users/{uid}/superAdmin`을 `true`로 설정한다. 앱 안에 "최초 슈퍼관리자 지정" UI는 만들지 않는다 (닭과 달걀 문제이고, 일회성 작업이라 콘솔에서 하는 게 더 간단함).
- 이후에는 기존 슈퍼관리자가 관리자 패널에서 **자기 소속 기관 멤버**를 슈퍼관리자로 지정/해제할 수 있다. 다른 기관 소속 사용자를 지정하는 기능은 이번 범위에서 제외한다 (다른 기관 멤버 목록을 읽으려면 별도의 교차-기관 읽기 권한 규칙이 필요해서 과한 확장).

## 로그인 화면 변경

- `formOrg` 탭("기관을 새로 등록")과 `doCreateOrg()` 함수를 제거한다.
- `formSignup`에서 "코드가 없다면 기관을 새로 등록하세요" 안내 문구도 제거한다.
- 가입코드로 합류하는 `formSignup` / `doSignup()` 흐름은 그대로 유지한다.

## 신규 기관의 "첫 관리자" 문제

슈퍼관리자는 기관과 가입코드만 발급할 수 있고, 그 기관 소속의 관리자 계정을 대신 만들어줄 수는 없다 (Firebase Auth 클라이언트 SDK 특성상 `createUserWithEmailAndPassword`를 호출하면 현재 로그인 세션이 새로 만든 계정으로 바뀌어버리기 때문에, 슈퍼관리자가 로그인한 상태에서 남의 계정을 만들면 슈퍼관리자 세션이 끊긴다).

**해법**: `registerMember(user, name, code)`에서 가입 코드로 합류할 때, 해당 `orgMembers/{orgId}`가 비어있으면(=그 기관의 최초 가입자) 자동으로 `role:'admin', approved:true`로 등록한다. 그 다음 가입자부터는 기존처럼 `role:'member', approved:false`(대기승인).

흐름: 슈퍼관리자가 새 기관 이름을 입력해 코드 발급 → 그 코드를 해당 기관 담당자에게 전달 → 담당자가 코드로 가입 → 자동으로 그 기관의 첫 관리자가 됨 → 이후 소속 직원들을 직접 승인.

## 관리자 모드 UI 추가

위치: 기존 `기관 관리` 탭(`admin.js` / `index.html`), `S.me.superAdmin === true`일 때만 노출되는 새 섹션.

1. **기관 추가 폼**: 기관명 입력 + "기관 추가" 버튼.
   - 클릭 시 `orgs/{orgId}` 생성, 6자리 코드 발급(`orgCodes/{code}`, `orgPrivate/{orgId}/joinCode`) — 기존 `doCreateOrg()`의 코드 발급 로직(충돌 시 최대 5회 재시도)을 그대로 재사용.
   - 발급된 코드를 화면에 표시하고 복사 버튼 제공.
2. **전체 기관 목록**: 지금까지 만들어진 기관들을 이름 + 코드 + 생성일로 나열, 각 행에 코드 복사 버튼. (코드를 잃어버렸을 때 다시 찾는 용도.)
3. **슈퍼관리자 지정/해제**: 기존 멤버 목록(`memList`)의 관리자/직원 토글 버튼 옆에, 슈퍼관리자만 보이는 "슈퍼관리자로/해제" 버튼 추가.

## Firebase 보안 규칙 (레포 밖, 콘솔에서 별도 적용 필요)

이 저장소에는 RTDB 보안 규칙 파일이 없어 현재 규칙을 정확히 확인하지 못했다. 이 기능을 실제로 안전하게 쓰려면 콘솔에서 아래 방향으로 규칙을 조정해야 한다:

- `orgs` 전체 목록 읽기: `auth != null && root.child('users').child(auth.uid).child('superAdmin').val() === true`인 경우만 허용.
- `orgs/{orgId}` 쓰기, `orgCodes/{code}` 쓰기, `orgPrivate/{orgId}` 쓰기: 슈퍼관리자만 허용하도록 제한 (현재는 `doCreateOrg`가 인증된 사용자 전체에 열려 있었을 가능성이 높음).
- `users/{uid}/superAdmin` 쓰기: 본인이 슈퍼관리자인 사용자만 (`같은 기관 소속`) 다른 사용자에게 부여 가능하도록 제한.

이 설계 문서 승인 후, 규칙 변경은 코드 변경과 별도로 사용자와 함께 콘솔에서 직접 확인하며 진행한다.

## 영향 범위

- `js/auth.js`: `doCreateOrg()` 제거, `registerMember()`에 최초 가입자 자동관리자화 로직 추가.
- `js/admin.js`: 슈퍼관리자 전용 섹션 렌더링/이벤트 함수 추가 (기관 추가, 기관 목록, 슈퍼관리자 토글).
- `index.html`: `formOrg` 마크업 제거, 관리자 탭에 슈퍼관리자 섹션 마크업 추가.
- `css/styles.css`: 필요시 소폭 스타일 추가 (기존 `.usr`, `.badge`, `.btn` 클래스 재사용 우선).

## 비범위 (이번에 안 하는 것)

- 다른 기관 소속 사용자를 슈퍼관리자로 지정하는 기능.
- 기관 삭제/이름 변경 UI.
- Firebase 보안 규칙 파일을 레포에 추가하는 것 (규칙은 콘솔에서 직접 관리되는 것으로 보임 — 별도로 원하면 추후 논의).
