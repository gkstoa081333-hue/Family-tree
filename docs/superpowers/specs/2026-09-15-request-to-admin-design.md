# "관리자에게 요청" 탭 설계

## 배경 / 목적

지금은 직원이 앱 기능개선 아이디어나 사용법 질문을 관리자(개발 주체인 슈퍼관리자)에게 전달할 방법이 앱 안에 없다. 로그인한 모든 사용자가 기능개선/질문을 보낼 수 있는 탭을 추가하고, 슈퍼관리자가 한 곳에서 모아 보고 텍스트로 답변할 수 있게 한다.

## 권한 모델

- **제출**: 로그인·승인된 사용자라면 기관/역할 상관없이 누구나 제출 가능.
- **수신/답변**: 슈퍼관리자만. 기관 자체 관리자(일반 `role:'admin'`)는 이 탭에서 다른 사람의 요청을 볼 수 없다 — 이번 범위에서는 기관별 문의 채널을 별도로 만들지 않는다 (비범위 참고).
- **열람**: 제출자는 본인이 보낸 요청과 그에 대한 답변만 볼 수 있다. 다른 사람의 요청은 볼 수 없다(슈퍼관리자 제외).

## 데이터 구조 (Realtime Database)

```
requests/{uid}/{requestId}
  ├─ id, uid, name, email, orgId, orgName   (제출자 정보 — 슈퍼관리자가 어느 기관인지 식별)
  ├─ type: 'feature' | 'question'
  ├─ title, content
  ├─ status: 'pending' | 'answered'
  ├─ createdAt
  └─ reply, repliedAt                        (답변 후에만 존재)
```

사용자 uid로 최상위를 나눈 이유: "내 요청만 읽기"를 Firebase 보안 규칙으로 깔끔하게 표현하려면 이 구조가 필요하다 (기존 `orgMembers/{orgId}/{uid}` 네임스페이스 관례와 동일한 방식). 슈퍼관리자는 `requests` 최상위 자체에 읽기 권한을 얹어(기존 `orgs`/`orgPrivate` 슈퍼관리자 읽기 권한과 동일 패턴) 전체 사용자의 요청을 한 번에 조회한다.

## UI

**새 탭 "관리자에게 요청"** — 사이드바(`aside nav`)와 하단 탭바(`.tabbar`)에 새 버튼 추가. `기관 관리` 탭과 달리 **모든 승인된 사용자에게 항상 노출** (역할/슈퍼관리자 여부로 숨기지 않음).

탭 콘텐츠:

1. **"+ 새 요청" 버튼** → 기존 `openSheet()` 모달 패턴 재사용. 유형 선택(기능개선/질문, `newCase()`의 공개범위 세그 버튼과 동일한 `segBind`/`segVal` 패턴), 제목(짧은 텍스트, 필수), 내용(textarea, 필수) 입력 후 제출.
2. **"내가 보낸 요청" 목록** — 실시간 리스너(`.on('value')`, 기존 `watchCases()`/`loadAdmin()` 패턴)로 본인의 `requests/{S.uid}`를 구독. 각 항목에 유형·제목·상태 배지(답변대기/답변완료) 표시. 답변완료면 관리자 답변 텍스트를 같이 보여준다.
3. **(슈퍼관리자 전용) "받은 요청 관리" 섹션** — `S.me.superAdmin===true`일 때만 노출 (기존 `기관 관리` 탭의 `superAdminPanel` 노출 패턴과 동일). `requests` 최상위를 실시간 구독해 전체 사용자의 요청을 모아 보여준다. 각 항목에 제출자 이름/기관, 유형, 제목, 내용, 상태를 표시하고, 답변 텍스트 입력창 + "답변 저장" 버튼을 둔다. 저장하면 `reply`, `repliedAt`을 쓰고 `status`를 `answered`로 바꾼다.

배지 문구·스타일은 기존 `기관 관리` 탭의 `승인 대기`/`관리자` 배지(`.badge`, `.usr` 클래스)를 그대로 재사용한다.

## Firebase 보안 규칙 (레포 밖, 콘솔에서 별도 적용 필요)

이번 기능도 이전 슈퍼관리자 기능과 마찬가지로 규칙 변경이 필요하다. 방향은 다음과 같다 (코드 작업과 별도로, 계획 완료 후 프로젝트 소유자와 함께 콘솔에서 확정):

- `requests/{uid}`: `.read`/`.write`는 본인(`auth.uid === $uid`) 또는 슈퍼관리자만.
- `requests/{uid}/{requestId}` 생성: 본인만, 그리고 `uid` 필드가 자기 자신과 일치해야 함.
- `requests/{uid}/{requestId}`의 `reply`/`status`/`repliedAt` 필드 수정: 슈퍼관리자만.
- `requests` 최상위 `.read`: 슈퍼관리자만 (전체 목록 조회용, 기존 `orgs`/`orgPrivate` 패턴과 동일).

## 영향 범위

- 신규 `js/requests.js` — 이 기능의 모든 로직 (제출 시트, 목록 렌더링, 답변 저장).
- `index.html` — 사이드바/탭바에 새 버튼, `#tabRequests` 컨테이너 마크업 추가. 스크립트 로드 순서에 `js/requests.js`를 `admin.js` 다음, `main.js` 이전에 추가.
- `js/cases.js` — `goTab()`의 3개 배열(`['tabCases','tabAdmin','tabMe']` 등)에 `requests` 추가. `enterApp()`에서 새 탭 초기화 함수(예: `loadRequests()`) 호출 추가 (기관관리처럼 조건부가 아니라 항상 호출).

## 비범위

- 기관 자체 관리자에게 보내는 별도 문의 채널 (이번엔 슈퍼관리자 전용).
- 답변에 대한 재질문/스레드형 대화 — 1요청 = 1답변으로 끝.
- 읽음/안읽음 세부 추적 — `pending`/`answered` 상태로 충분.
- 이메일/푸시 알림 — 슈퍼관리자가 앱에 들어와서 직접 확인.
